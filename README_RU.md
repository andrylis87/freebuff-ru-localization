# Русская локализация Freebuff CLI (ru-RU)

Патч добавляет русский язык в интерфейс Freebuff CLI: справку, меню
слеш-команд, статус-строку, поле ввода, экран входа, уведомления и системные
сообщения. Английский и китайская документация (`README.zh-CN.md`) не
тронуты, отсутствующие ключи продолжают отдавать английский текст.

- Ветка: `feat/i18n-ru`
- Патч: `freebuff-ru-localization.patch`
- Архив: `freebuff-ru-localization.zip`
- Глоссарий: [GLOSSARY_RU.md](./GLOSSARY_RU.md)

## 1. Как применить патч

Из корня репозитория, на чистом рабочем дереве:

```bash
git apply freebuff-ru-localization.patch        # вариант 1: как один патч
# или, чтобы сохранить авторские коммиты:
git am freebuff-ru-localization.patch           # вариант 2
```

Альтернатива — архив:

```bash
unzip freebuff-ru-localization.zip -d .          # файлы встают по своим путям
```

Если конфликт (локализация сделана по `origin/main` от 2026-10):

```bash
git apply --3way freebuff-ru-localization.patch
```

## 2. Как включить русский язык

Три способа, по приоритету:

1. **Команда в CLI** — сохраняется и переживает перезапуск:

   ```
   /language          # текущий язык и список доступных
   /language ru       # переключить на русский (алиасы: /lang, /locale)
   /language en       # вернуть английский
   ```

2. **Автодетект** — срабатывает только если язык никогда не выбирали
   вручную: `LANG`, `LC_ALL` или `LC_MESSAGES`, начинающиеся с `ru`
   (например `ru_RU.UTF-8`). Выбор пользователя всегда сильнее окружения.

3. **Переменная окружения** — явное принуждение, удобно для CI и баг-репортов:

   ```bash
   FREEBUFF_LOCALE=ru freebuff
   ```

Выбранное значение пишется полем `language` в `settings.json` каталога
конфигурации CLI (путь см. `getConfigDir()`, переопределяется
`FREEBUFF_CONFIG_DIR`).

## 3. Как собрать и запустить

```bash
bun install          # bun 1.3.14, lockfile не меняется
bun run dev          # dev-режим CLI (TUI)
bun run dev:freebuff # то же в Freebuff-режиме
bun run ci           # сборка sdk + freebuff
cd cli && bun run typecheck
```

Проверка локализации:

```bash
# из КОРНЯ репозитория (см. «Известные ограничения»)
bun test cli/src/i18n/__tests__/
```

## 4. Как это устроено

Решение минимальное: **новых зависимостей не добавлено ни одной** — только
`zustand`, который в проекте уже есть.

| Файл                                   | Роль                                                                                                                                                                            |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cli/src/i18n/index.ts`                | Ядро: `t(key, english, params)` — перевод с fallback, `tp()` — множественное число, `formatNumber`/`formatDate` на `Intl`, `useT()` — подписка React-компонентов на смену языка |
| `cli/src/i18n/types.ts`                | Тип `Locale`, список и подписи языков                                                                                                                                           |
| `cli/src/i18n/detect.ts`               | Автодетект из окружения и `Intl`                                                                                                                                                |
| `cli/src/i18n/locales/ru.ts`           | Каталог ru-RU: 135 плоских ключей                                                                                                                                               |
| `cli/src/utils/settings.ts`            | Хранение выбора (`language`), allowlist-валидация                                                                                                                               |
| `cli/src/index.tsx`                    | `initLocale()` при старте                                                                                                                                                       |
| `cli/src/commands/command-registry.ts` | Команда `/language`                                                                                                                                                             |
| `cli/src/i18n/__tests__/`              | 44 теста: ядро + проверка каталога                                                                                                                                              |

Ключевые свойства:

- **Английский живёт в коде**, в точке вызова: `t('help.title', 'Keyboard
shortcuts')`. Каталог хранит только русские переопределения, поэтому
  _отсутствующий ключ = английский текст_. Пустых строк и сырых ключей в UI
  не бывает.
- **Локаль по умолчанию `en`** и инициализируется только явно при старте —
  поэтому тесты, проверяющие английские строки, детерминированы на любой
  машине.
- **Множественное число по CLDR**: `one / few / many / other` через
  `Intl.PluralRules('ru')` — «1 сообщение», «2 сообщения», «5 сообщений»,
  «1,5 файла».
- **Плейсхолдеры не трогаются**: `{name}`, `{{name}}` подставляются,
  `${...}`, `%s`, `%d`, HTML и Markdown остаются как есть; незаполненный
  плейсхолдер остаётся видимым, а не превращается в пустую строку.

## 5. Что переведено

135 ключей, 50 вызовов `t()` и 15 вызовов `tp()`:

- меню слеш-команд (все описания команд, `/help`, `/plan`, `/model`, …);
- оверлей горячих клавиш (разделы «Ввод», «Чат», «Беседа», все подписи);
- статус-строка: «думаем…», «работаем…», «переподключено», повторы,
  переполнение очереди, «не удаётся связаться с серверами…»;
- поле ввода: подсказки всех режимов и бейджи «План», «Проверка»,
  «Собеседование», «Навык»;
- экран входа: инструкции, ошибки, кнопка копирования, таймаут;
- тосты и системные сообщения: ошибка отправки, копирование, `/copy`,
  `/usage`, обработка вложений;
- очередь сообщений (заголовок и пауза) и сводка изменённых файлов;
- новая команда `/language`.

## 6. Что НЕ переведено (и почему)

В CLI около 700 строк текста. Переведена «оболочка» — то, что видно в первые
десять секунд работы и в самых частых сценариях. Остальное сознательно не
тронуто в этом патче:

- рендеры вызовов инструментов (`components/tools/*`), блоки диалога
  агентов, панели `todo`/`queue`/`publish`;
- баннеры подписки и кредитов, рекламные/спонсорские блоки;
- селектор моделей и picker рассуждений;
- текстовые выводы команд `/byok`, `/deals`, `/ads:*`, `/diagnostics` —
  длинные технические инструкции с примерами команд и URL, где машинный
  перевод легко ломает копируемый текст;
- содержимое `agents/` (определения агентов) и `SKILL.md` — это контент,
  а не интерфейс;
- `README*.md` — документация, не UI.

Причина остановки — не архитектура, а объём: каждую строку нужно перевести
с сохранением плейсхолдеров и проверить компонентным тестом. Добавление
следующей порции не требует менять инфраструктуру — достаточно обернуть
строку в `t()` и добавить ключ.

## 7. Проверки, которые прогнаны

```bash
bun install --frozen-lockfile        # 670 пакетов, OK
cd cli && bun run typecheck          # 23 ошибки — БЕЗ моих правок их было 23,
                                     # вывод побайтово совпадает с базовым
bun test cli/src/i18n/__tests__/     # 44 pass, 0 fail
bun test <все 286 тестовых файлов>   # 3453 pass / 66 fail / 56 errors
bunx prettier --write <изменённые>   # OK
```

`66 fail / 56 errors` — **предсуществующие и окружные**, не связаны с
локализацией. Сверено на базовой ревизии теми же командами:

- `release wrapper` (3), `message history persistence` (3) — падают и без
  патча, причина в запуске из корня и в окружении;
- `display-ad-served` (2) — падают и без патча (ожидаются `codebuff.com`-URL);
- `freebuff-model-catalog` (3) и `Unhandled error between tests` в
  e2e/launcher-файлах — падают только в общем прогоне из-за перекрёстного
  состояния между файлами; те же файлы рядом с тестами локализации проходят.

Что **не удалось** прогнать и почему:

- `cd cli && bun test` — не стартует ни с патчем, ни без него:
  `cli/bunfig.toml` ссылается на отсутствующий в этом снапшоте
  `test/setup-scm-loader.ts`. Отсюда запуск из корня.
- `eslint` — в `package.json` нет скрипта `lint`, а `eslint.config.js`
  падает на отсутствующем пакете `globals` (та же проблема снапшота, что и
  `picocolors` в typecheck). Форматирование проверено `prettier`.
- Полную базовую сверку всего набора из 286 файлов выполнить не удалось:
  раннер перезапустился во время `git stash` → прогон → `git stash pop`
  (работа восстановлена из stash, потерь нет). Сверены все 11 уникальных
  падений — см. выше.

## 8. Известные ограничения

- Переводятся только строки, обёрнутые в `t()`/`tp()`. Необёрнутый
  английский в не переведённых файлах (раздел 6) остаётся английским — это
  осознанный fallback, а не ошибка.
- Реактивность: компоненты, использующие `useT()`, перерисовываются при
  смене языка сразу; строковые сообщения в обработчиках команд читают
  текущую локаль в момент вызова.
- Автодетект не срабатывает, если язык уже выбирали вручную (так и задумано).
- Русские строки длиннее английских. Проверено на самых требовательных
  местах: меню слеш-команд само переходит в двухстрочный режим, бейджи
  режимов ввода имеют `flexShrink: 0` и расширяются за счёт поля ввода,
  справка скроллится. На терминале уже 60 символов подписи переносятся по
  словам.
- Тест-кейс `ru.demo.*` — фикстура для проверки правил множественного
  числа, продакшн-вызова не имеет.

## 9. Предупреждение о лицензии

Проект распространяется по **Apache License 2.0** (`LICENSE`), в `NOTICE`
указано `Codebuff — Copyright 2025 Codebuff`.

- Право на модификацию и распространение производного кода у вас есть:
  Apache-2.0 это прямо разрешает.
- При публикации «русификатора» вы обязаны: сохранить файлы `LICENSE` и
  `NOTICE`, указать, что внесены изменения, и не удалять упоминания
  авторов. Убрать их — нарушение лицензии.
- Названия `Freebuff`, `Codebuff`, `Freebucks` — товарные знаки проекта.
  Использовать их в названии распространяемого патча можно только как
  описание совместимости («локализация для Freebuff»), а не так, будто она
  выпущена авторами проекта.
- Патч не содержит секретов, ключей, токенов и локальных конфигов — он
  меняет только исходники интерфейса, глоссарий и документацию.
- Если проект имеет отдельные ToS для hosted-части (бэкенд, сайт), они на
  этот локальный патч не распространяются: он меняет только клиент CLI.
  На всякий случай сверьтесь с `SECURITY.md` и условиями сервиса перед
  публикацией форка.
